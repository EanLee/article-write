## 🐛 發現的問題

### 1. Obsidian 圖片語法誤判 ⚠️

**問題描述**:
- `![[image.png]]` 被 `convertWikiLinks` 誤判為 Wiki Link
- 轉換結果: `![image.png](../imagepng/)` (錯誤)
- 預期結果: `![image.png](./images/image.png)` (正確)

**根本原因**:
- `convertWikiLinks` 的正則表達式 `/\[\[([^\]]+)\]\]/g`
- 無法區分 `[[link]]` 和 `![[image]]`
- 執行順序問題：convertWikiLinks 在 convertObsidianImages 之前

**影響範圍**:
- 使用 Obsidian 圖片語法的文章
- 圖片路徑會轉換錯誤

**優先級**: P1 (High)

**建議修復**:
```typescript
// 方案 1: 修改 convertWikiLinks 正則，排除 ![[]]
content = content.replace(/(?<!\!)\[\[([^#\]|]+)\|([^\]]+)\]\]/g, ...)

// 方案 2: 調整執行順序，先執行 convertObsidianImages
// 在 convertMarkdownContent 中調整順序

// 方案 3: 統一處理，在 convertWikiLinks 中檢查前一個字元
```

---

### 2. Slug 生成器移除中文 ℹ️

**問題描述**:
- 中文標題「相關文章A」→ Slug 只保留「a」
- `generateSlugFromTitle` 只保留 `[a-z0-9\s-]`
- 中文字元被完全移除

**影響範圍**:
- 中文標題的文章
- Slug 可能過短或不具意義

**優先級**: P2 (Medium)

**建議修復**:
```typescript
// 方案 1: 支援中文 slug (需要 URL encode)
generateSlugFromTitle(title: string): string {
  return encodeURIComponent(title.toLowerCase().replace(/\s+/g, '-'))
}

// 方案 2: 使用 Pinyin 轉換（需要第三方庫）
// 方案 3: 保持現狀，要求使用者提供英文 slug
```

**決策**: 待討論（涉及 SEO 和相容性）
