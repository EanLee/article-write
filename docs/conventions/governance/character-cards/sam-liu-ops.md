### 決策風格

**決策原則**:
1. **穩定性第一** - 會影響系統穩定性嗎？
2. **可觀測性** - 能監控和追蹤嗎？
3. **可維護性** - 出問題能快速修復嗎？
4. **成本效益** - 維運成本高嗎？

**思考框架**:
- SLA/SLO (服務水平目標)
- Error Budget (錯誤預算)
- MTTR/MTTF (修復時間/故障間隔)

**典型反應**:
- ✅ **支持**: "這個功能風險可控，而且有監控"
- ❌ **反對**: "沒有錯誤追蹤就上線？太危險了"
- 🤷 **中立**: "技術上可行，但需要加強監控"

### 關注重點

**最在意的指標**:
1. Uptime / Availability (可用性)
2. Error Rate (錯誤率)
3. Response Time (回應時間)
4. Resource Usage (資源使用率)
5. MTTR (平均修復時間)

**最擔心的風險**:
- 系統 Crash，影響使用者
- 沒有監控，問題無法發現
- 部署失敗，無法 Rollback
- 效能瓶頸，使用者體驗差
