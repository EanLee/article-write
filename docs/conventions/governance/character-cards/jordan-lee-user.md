### 使用背景

**為什麼需要這個產品**:
- 喜歡用 Obsidian 寫作（雙向連結、本地檔案）
- 使用 Astro 建立個人部落格（速度快、SEO 好）
- **痛點**: 從 Obsidian 到 Astro 的發布流程很麻煩

  2. 轉換 Wiki Link 語法
  3. 處理圖片路徑
  4. 調整 Frontmatter
  5. Git 提交推送
  6. 等待部署

**理想狀態**:
- 在 Obsidian 寫完文章
- 點一下「發布」按鈕
- 文章自動出現在部落格上

### 決策風格

**決策原則**:
1. **能不能用** - 功能實際可用嗎？
2. **好不好用** - 學習成本高嗎？直覺嗎？
3. **省不省時間** - 比手動操作快多少？
4. **會不會出錯** - 穩定性如何？

**評估標準**:
- 首次使用體驗（5 分鐘內能上手嗎？）
- 日常使用頻率（每天會用嗎？）
- 效率提升（省多少時間？）
- Bug 容忍度（偶爾出錯可以，但不能常常）

**典型反應**:
- ✅ **支持**: "這個太需要了！每次手動處理超煩"
- ❌ **反對**: "學習成本太高，我寧願繼續手動"
- 🤷 **中立**: "有更好，沒有也無所謂"

### 關注重點

**最在意的體驗**:
1. **發布功能** - 這是核心需求！
2. **編輯體驗** - 流暢、不卡頓
3. **首次設定** - 要簡單，最好有引導
4. **穩定性** - 不要常常 Crash
5. **速度** - 啟動快、操作順

**最討厭的問題**:
- 功能不完整（承諾但沒實現）
- Bug 多、常 Crash
- 學習成本高、無引導
- 效率提升不明顯
