# 技術團隊作業文件規範

## 何時必須建立文件（作業完成前）

- 建立或修改 CI/CD 流程
- 架構決策或技術選型
- 新工具、新服務的導入
- 基礎設施變更（Dockerfile、環境設定等）
- 跨模組的重構或整合
- 技術評估與方案比較

## 位置與命名

```
docs/<domain>/discussions/T-XXX-任務簡短描述.md
```

`<domain>` 依任務性質判斷；編號依序遞增，查看 `docs/conventions/governance/team-composition.md` 現有最大編號後加一。

## 必要內容

```markdown
# T-XXX 任務名稱

**日期**: YYYY-MM-DD
**負責人**: [成員名稱]
**狀態**: 📋 規劃中 / 🚧 進行中 / ✅ 完成 / ❌ 取消

## 任務背景
為什麼要做這件事

## 設計決策
技術選型、方案評估、最終決策及理由

## 實作說明
架構、流程、重要設定說明

## 相關檔案
列出所有新增或修改的檔案

## 相關 Commit
列出相關的 commit hash 與說明
```

## 技術討論文件化規則（必須即時，不得事後補寫）

- **討論開始時**立即建立 `T-XXX` 文件，狀態設為 `📋 規劃中`，並更新 `TEAM.md` 討論記錄索引
- 討論進行中：各成員觀點與評估即時寫入，方案比較表隨討論補充
- 決策完成後：狀態更新為 `🚧 進行中` 或 `✅ 完成`，確認決策理由已清楚記錄
- **禁止**：口頭討論完才回頭補文件、實作已開始但文件還是空白、文件只記結論不記過程

## 執行清單

技術作業前：
- [ ] 確認是否需要建立新的 `T-XXX` 文件
- [ ] 若是現有任務的延伸，更新對應文件

技術作業後（提交前必須完成）：
- [ ] 文件已建立或更新，包含設計決策與理由
- [ ] 相關 Commit 欄位已填寫
- [ ] 文件與程式碼一起提交
- [ ] `TEAM.md` 的討論記錄索引已更新
